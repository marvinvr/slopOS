# slopOS brief (from Marvin, 2026-10-29)

Build slopOS: a web-based desktop "operating system" whose apps are procedurally generated by Grok.

## Product
- A plain, beautiful desktop in the browser: wallpaper, menu bar (top: logo menu, active app name, app menus, clock, status icons), dock or launcher, draggable/resizable windows with traffic-light controls, focus/z-order, minimize/maximize.
- Spotlight-style search (Cmd/Ctrl+Space): search installed apps, and if nothing matches, offer "Generate '<query>' with Grok".
- App drawer / launcher with search (this replaces a real Settings app; settings don't need to exist).
- Should feel real and polished: subtle animations, keyboard shortcuts, sensible defaults, a few built-in apps (e.g. Notes, Calculator, Clock, Terminal-ish toy, About slopOS) also written in the same app format.
- Generated apps persist (server-side, e.g. a JSON/SQLite store + files) and show up in the drawer/search like built-ins; delete/regenerate/edit-with-prompt.

## Grok integration
- Backend uses the xAI Grok SDK/API (model: a Grok model with medium reasoning effort; make model + effort configurable). Key from `.env` `XAI_API_KEY` (never commit it). Without a key, the app must still run fully with built-in apps and a clear "Grok not configured" state.
- An easy, well-defined app interface so Grok can create apps in React: e.g. a single-file React component with a small `@slop/sdk` (window title/size, storage per app, notifications, theme tokens, fetch proxy if needed). Generation pipeline: prompt → Grok writes the component → validate/compile (esbuild/sucrase) → sandboxed load (iframe or isolated module) → on error, feed the error back to Grok for a fix attempt.
- Coherent style: a design system (CSS variables/tokens + a tiny component kit: Button, Input, List, Card, Tabs, etc.) that the SDK exposes and the generation prompt strongly instructs Grok to use, so generated apps look native to slopOS. Only "very slightly" opinionated, not heavy.

## Tech / ops
- Web based. TypeScript. Single `npm run start` serves the built frontend + API on 0.0.0.0, port 4747 (so Marvin opens http://mac:4747 via Tailscale). `npm run dev` for development on another port.
- mmux process `slopOS` (in mmux.yaml) runs `npm run start` and must stay up; restart it after builds.
- Git: local repo, commit to `main` (no remote yet).
